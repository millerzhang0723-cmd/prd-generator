# 单功能需求模板：表单页

> 适用：**单页或多步向导中的录入/编辑表单**；含分区标题、各类控件、提交/取消/保存草稿、字段校验、联动级联、**按业务生命周期或角色**的禁用/置灰与按钮显隐。  
> **编排位置**：交付稿中置于 `## 3 产品需求详述` 下，作为 `### 3.x.x …` 功能小节（**勿把本 `>` 说明块原样复制进对外 PRD**）。  
> 结构对齐列表/卡片页范式：**1 原型截图 → 2 功能说明 → 3 字段说明 → 4 异常情况说明 → 5 状态与操作关系（流程示意图）**。其中「字段」含**页面标题/面包屑、分区标题、说明文案、每个表单项、辅助 icon、刷新/外链、底部主辅按钮**等，不仅指业务数据列。  
> **默认交互**：凡会发起请求的按钮（提交、保存草稿、下拉旁的**刷新备选项**、弹窗确定等），须在「字段说明」中写明 **loading 展示 + 请求中禁用**，结束后恢复，防止连续点击重复提交（与 **2.4 全局交互与展示约定**、[`references/global-ui-conventions.md`](../references/global-ui-conventions.md) 一致）。  
> **主内容加载**：表单依赖接口拉取主数据、字典或级联选项且耗时可感知时，须有 **区块/整页 loading**（未约定时可写「同 2.4」）。  
> **文字超长**：只读展示、标签、提示等因空间有限展示不全时，按 **2.4**：末尾 **「…」/「...」** + **鼠标悬停气泡**展示全文。

（小节标题示例：`### 3.x.x 功能名称`；首段可写一句总述，如：「用于新建/编辑 xxx，提交后返回列表/进入下一步。」）

## 3 字段说明

下列对象统一填入本表：**面包屑/页标题、各分区标题与说明、每个表单项（含标签、输入区、辅助说明）、信息 icon、与下拉绑定的刷新按钮、「去新建」类外链、底部按钮**等。  
列含义：**字段名称**为界面展示名或控件名；**字段说明**为行为与业务含义；**约束条件**含类型、枚举、默认值、必填、长度、格式、联动、备选项来源与排序规则等；**示例**填示例值或示例文案；**注释**填**不同生命周期/角色下的可编辑性**、权限、与原型差异、计算规则、与校验表的引用等。  
对**会触发接口的控件**，在「字段说明」或「注释」中须写清：**loading 形态**、**进行中是否禁用**、失败/成功后如何恢复可点。

**撰写粒度参考**（与业务示例文档一致时可展开到行级）：

- **分区**：一级/二级标题、分隔线，仅作视觉分组时也要占一行说明「无业务提交字段」或「仅承载下列子项」。
- **下拉/远程搜索**：备选项**数据来源**（菜单路径或接口对象）、**排序规则**（字母/拼音/业务序）、是否**模糊搜索**、与父字段的**级联**关系。
- **下拉旁刷新**：点击后刷新备选项、是否清空已选、是否显示 loading；与**无数据提示**、**无权限提示**的展示条件（见下行）。
- **无匹配/无权限时的提示与外链**：无备选项或用户无「新建」权限时，**两行提示语**须分别写清（见下表示例行）。
- **复合行**：一行内多个控件（如「字段 A + 大于号展示 + 字段 B」），可拆为多行或用「复合字段-xxx（子项1）」形式逐行写清。
- **Checkbox + 关联输入**：勾选显隐、默认值、勾选与必填校验的关系。
- **只读与置灰**：除「查看页只读」外，若存在 **业务状态**（如任务未启动可改、已成功后不可改），在「注释」列**按状态逐条**写明（可与第 5 节互链）。

| --- | --- | --- | --- | --- |
| 面包屑 / 页面标题 | 展示层级与当前页标题；是否可点击返回上级 | 文本/链接 |  | 与路由、浏览器返回关系 |

## 4 异常情况说明

描述**表单在数据或请求异常时的界面表现与交互**，避免仅依赖原型而未约定文案与行为。  
与第 3 节对照：主数据加载失败、选项加载失败、提交失败、并发冲突、权限变更等。


| 场景 | 界面表现 | 文案/操作示例（可替换为实际稿） | 备注 |
| --- | --- | --- | --- |
| 主数据/表单草稿加载中 | 整页或内容区 **Skeleton / Spin** | — | 是否阻塞底部按钮 |
| 主数据加载失败 | 错误提示区或 Toast；是否保留重试 | 「加载失败，请重试」 | 重试是否重新拉取全量 |
| 下拉备选项加载失败 | 表单项错误态；下拉内提示 |  | 是否允许手动输入兜底须约定 |
| 提交失败（业务错误码） | 字段级错误 / 全局 Toast | 与后端 message 映射关系 | 是否定位到字段 |
| 网络超时/断网 | Toast；已填内容是否保留 |  |  |
| 并发编辑/数据已被修改 | 提交时版本冲突提示 | 「数据已更新，请刷新后重试」等 | 刷新后是否丢本地修改 |
| **并发创建冲突（同名）** | 用户 A 新建填写中，用户 B 已用相同唯一键（如名称）创建成功；A 提交时后端返回唯一性/重复错误 | 如：「xxx 名称已存在，请修改后重试」；焦点落到名称字段或高亮该字段 | 与 3.1 唯一性规则、错误码映射；是否保留已填其他字段 |
| **创建过程中权限被收回** | 填写过程中管理员收回「新建/编辑」等权限；用户点击提交时接口返回无权限 | 如：「您暂无 xxx 权限，请联系管理员」；停留当前页或引导返回列表 | 与路由守卫、提交前是否预检权限（可选） |

| 取消时存在未保存修改 | 二次确认弹窗（如有） | 「已修改内容将丢失，是否离开？」 | 与「保存草稿」组合规则 |

## 5 状态与操作关系（流程示意图）

描述**业务对象生命周期**（如草稿、待启动、运行中、成功、失败）或 **页面模式**（新建/编辑/查看）与 **字段可编辑性、主按钮可用性、辅助按钮（刷新、外链）显隐** 的对应关系；与「首次启动成功前 / 运行成功后」类条款一致时，在此集中定义，字段表可用「同第 5 节」引用。  
建议使用 **Mermaid** `flowchart`/`stateDiagram` 或「状态-字段/按钮」对照表；复杂时补充编号条款。


```mermaid
flowchart TB
  subgraph 示例
    A[草稿/未启动] -->|提交并启动成功| B[已运行]
    B -->|成功后| C[部分字段只读]
  end
```



**文字条款示例（按需保留或改写）：**

1. **模式矩阵**：新建 / 编辑 / 查看下，各分区或各字段是 **可编辑 / 只读 / 隐藏**（可用表格附后）。
2. **业务状态矩阵**：状态 S1…Sn 下，哪些按钮显示、哪些字段置灰；是否与 **角色权限** 取交集。
3. **刷新按钮与外链**：何种状态下隐藏「刷新」「去创建」（避免误导不可变更项）。
4. **提交成功后**：跳转列表、详情或关闭弹窗；是否刷新父页面。
5. **与列表/详情联动**：返回列表后是否需刷新某行（与第 4 节 Toast 策略一致）。

（无流程图可表但需约定的边界场景，可在此节下延续编号列出；与第 4 节重复的边界可择一处详写、另一处引用。）

**验收要点（测试可读，按需删改）：**

1. 入口与模式（新建/编辑/查看）与原型、路由一致。
2. 各字段：默认值、默认提示语、占位符、必填、长度、格式、枚举与「字段说明」一致。
  a.比如输入框，需要包括填写内容的长度限制，特殊符号限制，默认提示语显示，默认值内容，是否唯一，是否必填等内容描述；
  b.比如下拉选择器，需要包括单选还是多选、是否支持关键词搜索、被选项来源或备选项内容、被选项排序策略、默认选项、是否必填。
3. 联动与级联：父变子清空、备选项来源与排序正确。
4. 校验：触发时机、错误文案、与 3.1 一致；无重复提交。
5. loading 与禁用：提交、刷新备选项等符合 2.4；结束后恢复可点。
6. 异常与权限：第 4 节各场景表现与文案符合约定（含**并发创建同名**、**提交时权限已收回**）。
7. 生命周期/状态下置灰、刷新与外链显隐与本节状态矩阵一致。
