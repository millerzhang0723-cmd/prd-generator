# 生成后三角色自查与定稿修订（与 SKILL 配套）

> **（给智能体）**本文对应主 Skill 中 **「操作步骤」第 7 步**：在产出 PRD 初稿后、交付用户前执行。**每轮必做、由智能体自动执行**，**不要**等用户再说「请自查」「复核」「过三角色」才打开本文；除非用户在本轮**明确**要求跳过。全文为**内部分析与改写依据**；**不要**把本文标题或条目整段复制进用户 PRD，也不要在 PRD 里写「三角色自查文档」等元字样。

## 执行时机

每一轮**已写出 PRD 初稿**之后、**作为最终交付发出之前**，智能体须**自动**跑完全文流程，**无需用户二次触发**；若同一轮内对同一稿多次改写，在**最后一次准备发出给用户前**执行一次即可。用户显式说「跳过三角色自查」时省略。

## 与「读者可见正文」的边界

本文件的检查项是**智能体内部分析框架**；修订成果体现在 **1～9 各章与 3 下各小节** 的正文表述、表格与 **「8 待完善」** 中。**不要**在 PRD 里新增「产品自查」「开发自查」「测试自查」等章节或附录，也不要照抄本文条目进正文（除非用户明确要求附录式评审记录）。

## 修订原则

能当场改写的矛盾、遗漏、歧义**直接改 PRD**；仍缺材料或缺业务决策的，**不写死**，改为 **待确认** 或写入 **「8 待完善」**；不因「想显得完整」而虚构接口、权限或枚举。

## 1. 产品经理视角（目标、范围与策略自洽）

从**目标与范围是否闭环**出发，自问并核对 PRD 是否已体现或已标清：

- **叙述一致性**：**1.2 需求范围**、**2.3 流程**与 **3 产品需求详述** 是否同指一件事；有无「概述说做 A、详述只做 B」或重复、冲突描述。
- **用户与价值**：**1.3** 与功能主路径是否匹配；是否说清了**成功标准**或可归因的**业务结果**（而非仅罗列控件）。
- **策略与 AI 类**（若适用）：输入输出边界、效果预期、降级与人工介入是否与业务风险匹配；Bad Case 与 **6 风险分析** 是否呼应。
- **名词与口径**：**1.5** 与正文术语是否一致；跨小节同一实体是否同名。
- **依赖与边界**：外部系统、数据归属、谁配置谁使用等是否在 **2** 或 **3** 中交代清楚，避免默认「对方系统已具备」。

## 2. 开发视角（可实现、可对接、可维护）

从**能否按文档开工与联调**出发，检查并补写至可落地粒度（仍遵守「不臆造」：未知写 **待确认** / **8 待完善**）：

- **状态与数据**：列表/表单/详情涉及的关键**状态**（空、加载、失败、无权限、进行中、终态）是否齐全；核心对象**生命周期**是否与接口或任务语义一致（若材料未给接口名，可写业务语义级「须持久化 / 可重试」等，勿编字段名）。
- **交互与 2.4**：写操作、异步、防连点、loading、错误提示、超长文案等是否与 **2.4** 及模板要求一致；有无只写「点击提交」却无失败与超时后果。
- **权限与安全**：若材料提及角色或敏感操作，是否写明**可见/可操作**边界；删除、导出、批量等是否需二次确认或留痕（材料未提则 **待确认**）。
- **兼容与迭代**：局部迭代是否写清**旧逻辑**与**回归范围**；新旧并存时默认策略是否矛盾。
- **技术依赖**：**6** 或 **3** 中是否点出关键依赖（第三方、配额、浏览器环境等），避免评审时才暴露。

## 3. 测试视角（可测、可验收、逆向与异常）

从**能否直接派生用例**出发，检查并补强条目化描述：

- **页面类附图**：各详述小节 **「1 原型截图」** 是否含 **`![](相对路径)`**（或多张），或已写清**约定路径 + 保存原图提示**；避免仅「见对话附件」而无任何可随仓库预览的引用。
- **Mermaid 可渲染性**：带 `mermaid` 语言标记的代码围栏与 `flowchart` 语法是否合规；**含 `+`、`/` 等**的节点展示文案是否已用**双引号**包住；是否**误用** `A & B & C --> D` 多路连写（应拆成多行 `A --> d`、`B --> d` 等，见主 **SKILL**「注意事项 · 图表（Mermaid）·**为 PRD 可渲染、少踩坑的 Mermaid 写法**」）；**节点 id** 是否仅用英文/数字/下划线；**节点方括号内是否误写 Markdown 加粗**（成对 `**` 会破坏 Mermaid 解析），避免 PRD 中只显示源码、图不渲染。
- **主路径与分支**：每条主路径是否有**前置条件、步骤、期望结果**；关键分支（条件不同、权限不同）是否可区分验收。
- **逆向与「作死」路径**：取消、关闭弹窗、重复提交、断网刷新、超时重试、并发编辑、越权访问、空数据提交、非法格式、上限边界（条数、长度、频率）等是否**有预期行为**或明确 **待确认**。
- **数据与幂等**：删除/作废是否可恢复或是否硬删；重复请求、部分成功/失败时列表与提示是否一致。
- **埋点与数据（若已写 4/5）**：**4** 中事件与 **3** 中操作是否一一对应、属性可分析；**5** 若展开，是否侧重**历史/迁移/冷启动**等，**未**在 **5** 中无意义地重复各 **3.x** 已写的功能级数据口径（口径应在 **3** 中可验收）。
- **风险可测**：**6** 中的风险是否在 **3** 中有对应缓解或验收关注点（或标为上线后监控）。

## 4. 定稿动作（合并修订）

1. 汇总三视角下可**确定性修订**的问题，**就地修改** PRD 各节措辞、列表、表格与流程说明。
2. 仅能判断「有问题、无材料定论」的项，写入 **「8 待完善」** 或在正文中 **待确认**（附一句缺什么信息）。
3. **6 风险分析** 若在三视角下发现新风险，补充条目；与业务无关的纯工具元风险不必写入 PRD。
4. 再次快速扫读：**标题与编号**仍符合标准目录；**不出现**模板文件名、Skill 名、「骨架」等禁用元信息（与主 Skill「读者可见正文 vs 内部编排」一致）。

## 与主 Skill 操作步骤第 7 步的对应关系

对本轮拟交付的 PRD Markdown（无论是仅 **3 产品需求详述** 小节还是**完整 PRD**）：

- **默认**：按上文 **执行时机 → 三视角 → 定稿动作** 完整走一遍，**在同一轮对话内自动完成**，不依赖用户追加指令；
- 将发现的问题**改写进 PRD 条款**（补漏、去矛盾、强化验收与风险），**禁止**把自查清单全文、分角色对话记录或「以下为自查结果」类元叙述写入 PRD 正文；
- 若用户只要 PRD、不要过程说明，对话里也可不展开自查细节，仅交付**已按三视角修订后**的终稿。
