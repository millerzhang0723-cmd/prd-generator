# PRD 各章节写作要点（与 SKILL 配套）

> **（给智能体）**本文仅供内部对齐口径；**不要整段复制到用户 PRD**，也不要在 PRD 里写「配套 SKILL」「写作要点文档」等字样。

本文与 [`full-prd-skeleton.md`](full-prd-skeleton.md) 一致：**共 9 个顶级章节**，其中「1 概述」「2 全局说明」下含小节（1.1～1.5、2.1～2.4）。供智能体在「补全产品需求详述以外的章节」时查阅。

## 产品需求详述与其他章的顺序

- **先写「3 产品需求详述」**：按原型截图逐页/逐功能输出，使用 `template/` 中匹配的类型模板；**「1 原型截图」** 须用 **`![](相对路径)`** 嵌入图（见主 Skill **注意事项 · 原型图嵌入**），勿仅文字描述。
- **后写其余章节**：在全部功能详述就绪后，再写 **1、2** 各节及 **4～9**，避免前后矛盾。

## 「3」与「5 数据需求」的分工

- **3 产品需求详述**（各 `### 3.x` 下）：在字段说明、接口与展示、验收要点中落实**本功能/本页**的**数据口径、来源、何时刷新/是否近实时、权限与脱敏**等——**与研发实现、用例、界面一致**，优先写在这里。
- **5 数据需求**（全章，产品级/跨功能）：**历史**数据如何**继承、迁移、割接**；**冷启动/预置**要灌哪些**字典、种子、批处理**；**存量/增量/回灌**范围；需单独约定的**对账、批作业**与多系统**数据一致**等。**不要**在 **5** 中整章重复各 **3.x** 已写过的单功能指标定义，仅可在 **5** 中做**汇总的跨功能数据策略表**（若确有需要）。

## 「2 全局说明」— 2.4 全局交互与展示约定

完整条文见 [`global-ui-conventions.md`](global-ui-conventions.md)；汇编完整 PRD 时**须包含**本节（可与骨架 `2.4` 摘要一致，或直接拷贝参考文档正文）。默认五条为：

1. **按钮**：防连续点击 + 点击后 loading + 结束后恢复。
2. **列表排序**：未单独约定时，默认 **操作时间倒序**（见参考文档口径）。
3. **加载反馈**：列表、表单主区、图表等 **可感知加载** 须有 loading，避免白屏。
4. **超长文案**：省略号截断 + **悬停气泡（Tooltip）** 展示全文（移动端替代方式见参考文档）。
5. **进行中状态**：任务/流程等状态从进行中到终态须 **自动更新界面**，无需人工刷新整页（降级与手动刷新入口见参考文档）。

与产品需求详述的关系：某功能小节若已写明不同规则，以该小节为准；否则遵循 2.4。

## 全局交互默认值（写入各功能详述时的对照）

- **防重复点击**：与 2.4 第 1 条一致；所有会发起请求或产生副作用的按钮/主操作，须约定：**loading + 禁用再次点击**（或「整表单/弹窗级」禁用策略），结束后恢复。
- **与验收的关系**：可在各功能模板「验收要点」中增加「请求中不可重复触发」类可测条目；与各详述小节的字段/交互说明一致。

## 图表

- 在 Markdown 中使用 **Mermaid** 时，须以代码块围栏包裹，**首行语言标记为** `mermaid`，其余语法与主 **SKILL** 中 **「注意事项 · 图表（Mermaid）」** 一致。
- **`flowchart`**、**`sequenceDiagram`**、**`stateDiagram-v2`** 在常见预览与文档站中**兼容性较好**。
- **`mindmap`** 在较新 Mermaid 中可用，但 **GitHub 及部分 Cursor/VS Code 内置 Markdown 预览可能不渲染**；**需要广泛兼容**时，**不要依赖** `mindmap`，**优先**用 `flowchart TB` / `flowchart LR` 表示层级、导航或模块划分；与 `full-prd-skeleton.md` 中 2.1 节表述一致。
- **避免整图不渲染**（`flowchart` 常见原因）：`[]` 内展示文案若含 `+`、`/` 等，须用**双引号**包住整段；**不要**使用 `T2 & T3 & T4 --> n` 类多路简写，应拆成多行**单源**指向同一 `n` 的连线；详见主 **SKILL**「注意事项 · 图表（Mermaid）·**为 PRD 可渲染、少踩坑的 Mermaid 写法**」各条。
