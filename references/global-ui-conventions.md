# 全局交互与展示约定（嵌入 **2.4 全局交互与展示约定** 时使用）

> **（给撰写者）**与 `[full-prd-skeleton.md](full-prd-skeleton.md)` 中 **2.4 全局交互与展示约定** 一致；撰写完整 PRD 时可将本节全文置于 **「2 全局说明」** 下对应小节，或在 2.4 中写「见本文档」并保留标题与编号。**勿在对外稿中保留本提示行。**

以下为产品级默认约定；若某列表/某页在**产品需求详述**中**已单独写明**排序、loading、截断规则或**状态刷新策略**，则以**该功能详述为准**。

## 1. 按钮防连续点击与 loading

所有会触发接口请求、写操作或副作用的按钮（含工具栏、查询/提交、行内操作、弹窗「确定」等），用户点击后须：

- 进入 **loading** 状态（按钮内菊花、文案如「提交中…」等，与 UI 规范一致）；
- **禁用**该按钮（或约定整表单/整弹窗主操作级禁用，二选一须写清），防止连续点击导致重复提交、重复任务或重复计费；
- 请求 **结束**（成功或失败）后恢复为可点击。

纯前端、无请求的交互（如展开/折叠、切换 Tab）不适用本条；一旦与请求绑定则同样适用。

## 2. 列表默认排序

**列表页**若在需求中**未另行说明**排序方式，默认按 **操作时间倒序**排列（最新操作记录在前）。

- 若后台字段名为「更新时间」「最后操作时间」等与「操作时间」等价，在首次出现的列表功能详述中注明字段口径即可。
- 若某列表业务上必须固定其他排序（如按名称、优先级），须在**该列表**对应功能小节中单独写明，覆盖本默认约定。

## 3. 列表、表单、图表等内容的加载反馈

**列表区域、表单主内容区、统计图/图表区块**等依赖接口或计算、且加载 **时长可感知**（非瞬时）时，须有明确的 **loading 反馈**，例如：

- 列表：表格骨架屏、区块 spinning、首次加载占位等；
- 表单：主数据未返回前区块 loading；
- 图表：指标卡/图形占位与加载动画。

避免长时间 **白屏或完全静态空白**；具体形态可与设计规范、组件库对齐，并在各页功能详述中按需要细化。

## 4. 文字超长：省略号 + 悬浮展示全文

当展示空间不足、无法完整显示文案时：

- 在可视范围内展示 **尽可能多的字符**，超出部分用省略号截断（**「…」** 或 **「...」**，与项目文案规范一致）；
- **鼠标悬停**时通过 **气泡（Tooltip）** 展示 **完整内容**；
- **移动端**无悬停时，可采用长按或点击展开等方式展示全文，若与 Web 不一致，在对应功能详述中按页面或按端单独约定。

## 5. 进行中状态的自动更新（无需人工刷新整页）

当界面展示**会随后台或异步流程变化的状态**（例如任务、作业、流程节点的执行状态：**进行中** → **已完成** / **失败** / **已取消** 等），在用户**停留在当前页、未手动刷新浏览器**的前提下，状态变更须在合理时间内**自动反映到界面**，**不要求**用户依赖 **F5**、浏览器刷新或列表「刷新」按钮才能看到终态。

**典型示例**：列表页某一行的任务为「进行中」，后台任务结束后，该行应**自动**变为「已完成」（或对应终态），并与状态相关的**操作按钮**一并更新（例如由「终止」变为「查看结果」）。

**撰写 PRD 时的要点**：

- 明确 **哪些字段/标签**属于「会持续变化直至终态」的状态展示；
- 约定 **自动更新后的界面表现**（状态文案、标签色、行内操作显隐）；
- 可选：对 **更新时效** 或 **刷新频率上限** 提出产品预期（避免长时间停留在错误状态），具体技术实现（轮询、WebSocket/SSE、推送等）由研发选型；
- **异常与降级**：请求失败、断网、长连接不可用时，是否 Toast 提示、是否提供「手动刷新」入口，在具体功能详述或本节延伸说明。

若某列表明确为「仅手动刷新才更新」或静态报表**不需要**实时状态，在该列表的功能详述中单独写明，可偏离本条默认约定。

## 5. 默认时间格式

1、日期：yyyy-MM-dd
2、日期时间：yyyy-MM-dd hh:mm:ss
3、时间：hh:mm:ss
